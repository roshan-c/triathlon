# Unified access keys with audit-only automation identities

Triathlon uses one access-key mechanism for human-owned tools and automations instead of separate personal and agent credentials. An Automation belongs to one user and inherits that user's permissions; tickets, assignments, reviews, and project activity attribute its work to the user, while the owner-only security audit records the Automation and key that actually made the request. Keys are project-scoped by default and may be non-expiring. An Instance Admin may issue an explicitly marked instance-wide key, expiring within 90 days, that grants ordinary member-level work access across every current and future project but never grants project administration. Optional client headers distinguish CLI, agent, and other callers in audit records but grant no authority, because they are untrusted metadata.
