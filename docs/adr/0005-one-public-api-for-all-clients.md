# One public API for all clients

Triathlon v2 exposes one versioned HTTP/JSON API, documented by a public OpenAPI document, for the separately distributed first-party web UI, third-party frontends, the CLI, and automations. Browser sessions and access keys select authentication and authorization policy at the same API seam, with credentialed browser origins explicitly allowlisted. Resource endpoints handle reads and basic edits, explicit command endpoints enforce lifecycle transitions, and deep composite reads expose project summary, board snapshot, Frontier, ticket detail, and sprint metrics without agent-only logic. Resource versions prevent lost updates, seven-day idempotency records make retries safe, and board reordering is atomic. Errors share one Problem Details-style contract with stable domain codes. Ordered, resumable project-scoped Server-Sent Events use a versioned envelope and person-level attribution; authenticated capability discovery reports effective identity and scope. Fastify route schemas generate the checked-in OpenAPI document, which in turn generates an optional TypeScript client; neither the web UI nor server modules share handwritten transport types. The `/api/v1` contract permits additive changes only, with breaking changes requiring a new major path and one documented transition release. There is no separate agent gateway with duplicated application logic; agent-specific discovery or protocol support remains a thin adapter, and MCP is deferred until a concrete need emerges.
